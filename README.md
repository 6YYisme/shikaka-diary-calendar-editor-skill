# 食物手账贴纸批量生成

用于批量制作「日记 / 月历 / 运动月历」中的食物手账贴纸效果。

项目的核心目标不是重新设计 App
UI，而是在**保持原始截图完全一致**的基础上，把食物照片处理成自然、真实的手账贴纸，并放到截图中的合适位置。

详细视觉规范见
[`FOOD_STICKER_STYLE_GUIDE.md`](./FOOD_STICKER_STYLE_GUIDE.md)。

## 核心原则

输入截图必须视为**不可修改的底图**。

-   保持原截图尺寸、分辨率、长宽比完全一致。
-   不重绘 UI，不修改文字、数字、日期、按钮、图标、字体、颜色和位置。
-   只增加食物贴纸，以及任务明确要求的热量/手账标注。
-   不为了放贴纸重新排版。
-   输出前必须和原图对比，除新增内容外不应发生变化。

## 食物贴纸的目标质感

最重要的关键词不是"精致"，而是：

**普通人日常生活 / 手机随手拍 / 真实光影 / 抠图贴纸 / 平凡无奇的画质。**

想象用户吃饭时随手用 iPhone
拍了一张，然后直接把照片中的食物抠出来贴进电子手账。

必须保留真实照片本身的差异，例如：

-   自然环境光和轻微阴影；
-   不完全均匀的曝光；
-   不同照片各自不同的色温；
-   不同食物不同的亮度和饱和度；
-   普通手机拍摄的清晰度和噪点；
-   不规则、真实的食物形态和容器。

**不要把所有贴纸统一调成同样的亮度、饱和度、色温和锐度。**

禁止摄影棚布光、商业美食广告、电商产品图、HDR、过度锐化、统一高饱和、塑料感、3D
渲染感、AI 插画感以及"同一素材库"的整齐感。

## 贴纸处理

优先从真实照片中抠出盘子、碗、杯子、包装和食物主体。保留食物原本光影，在主体外围增加**细而自然的白色手账描边**，可有非常轻微的纸片阴影。

白边不要过厚，不要把真实食物做成卡通素材。

## 日记排版

日记页面通常放 3--6 个贴纸即可。

贴纸大小略有差异，可以轻微错落，但必须保留明显留白。不要遮挡标题、日期、心情、体重、照片栏或其他
UI，也不要为了"丰富"而填满页面。

## 月历 / 运动月历排版

月历中的贴纸要明显更小。

日期、热量、运动时长、运动类型等原有信息必须继续清晰可读。贴纸只是辅助记录，不需要强行填满每一天；原本无记录的日期可以继续留空。

尤其避免把月历做成尺寸完全一致、角度完全一致的"食物图标矩阵"。

## 热量标注

仅在任务明确要求时增加热量，例如：

`牛肉面 520 kcal`

或：

`520 kcal`

没有可靠数据时，**不要自行编造精确热量**。

## Codex 任务指令

新任务可直接使用：

``` text
请先读取 README.md 和 FOOD_STICKER_STYLE_GUIDE.md，并严格按照其中的规范完成本次任务。

输入文件：inputs/
视觉参考：references/
输出目录：outputs/

执行要求：
1. 输入截图是不可修改的 UI 底图。
2. 输出图片尺寸、分辨率、长宽比必须与输入完全一致。
3. 禁止重新生成、重绘或重新排版 UI。
4. 原有文字、数字、日期、按钮、图标、颜色和位置全部保持不变。
5. 只在合适的区域增加食物手账贴纸。
6. 优先使用输入的真实食物照片抠图；如需生成食物，也必须模拟普通手机随手拍照片抠图后的质感。
7. 食物不要摄影棚感、商业美食摄影感、统一高饱和或 AI 塑料感。
8. 不同食物保留各自不同的光线、色温、亮度、饱和度和普通手机画质。
9. 给食物增加自然、较细的白色贴纸描边和非常轻微的阴影。
10. 贴纸尺寸克制，页面必须保留留白。
11. 月历贴纸尤其要小，不得遮挡日期和原有数据。
12. 原本没有记录的日期不要擅自填满。
13. 没有可靠热量数据时，不自行编造热量。
14. 输出前逐张与输入原图进行像素尺寸及视觉对比，确认除新增贴纸/指定标注外 UI 没有变化。
```

## 批量输出检查

每张图完成后检查：

-   尺寸和分辨率是否与输入一致；
-   长宽比是否一致；
-   UI 是否被修改或重新生成；
-   原文字、数字和日期是否被误改；
-   贴纸是否遮挡原有内容；
-   贴纸是否过大；
-   页面是否太满；
-   食物是否出现摄影棚/商业美食质感；
-   不同食物是否错误地拥有完全一致的亮度、饱和度和色温；
-   是否仍有普通手机随手拍的自然光影；
-   白色描边是否自然；
-   是否出现明显 AI 生成痕迹。

UI 发生非指定变化时，应视为失败，不要将该图作为最终输出。

## 判断优先级

发生冲突时严格按照：

**原 UI 完整性 \> 原图尺寸比例 \> 食物真实感 \> 合理留白 \> 贴纸美观度
\> 装饰丰富度**

宁可少贴几个，也不要遮挡 UI。

宁可食物看起来普通，也不要做成摄影棚美食图。

宁可保留照片之间的色差，也不要为了"统一"给所有食物套同一个滤镜。

## 最终标准

最终效果应该让人感觉：

> 这是用户把自己日常吃饭时随手拍的食物抠出来，贴进了自己的饮食日记。

而不是：

> 这是 AI 生成了一套精致统一的食物素材，然后重新设计了一张 App 页面。
